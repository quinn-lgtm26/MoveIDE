updated: 2026-11-07T14:34

- (direction) Quinn asked to open MoveIDE to goal-oriented skills (free throw, squat, push-up, volleyball spike) via a biomechanics-grounded charter that accounts for height and segment lengths.
- (decision) Mode express: input is a rich in-chat design; no guided elicitation.
- (decision) Post-hackathon scope; does not change the squat-only hackathon build or Seldon baseline.
- (decision) Three layers: universal Charter, declarative per-skill protocols, per-person body profile.
- (decision) Charter fills the existing charterVersion slot in CoachPacket v1; no new packet field for it.
- (capability) CAP-1 Charter: versioned universal principles (base of support/CoM, proximal-to-distal sequencing, stretch-shortening cycle, range of motion, posture/alignment, consistency), each mapped to a video proxy.
- (capability) CAP-2 Skill protocol: one data file per skill declaring view, min fps, required landmarks, phases/events, metrics, and Charter principle per metric; adding a skill needs no engine code when primitives suffice.
- (capability) CAP-3 Primitive library: shared event detectors (angle extremum, CoM vertical velocity zero-crossing, ground contact from ankle velocity, release from wrist peak velocity) and metric primitives (joint angle, segment-to-vertical, angular velocity, peak-timing lag, normalized CoM displacement).
- (capability) CAP-4 Body profile: segment lengths estimated from pose (standing frame or per-segment clip max), metrics normalized by segment length, profile carried in report so interpretation can excuse proportion-explained deviations.
- (capability) CAP-5 Unknown-movement mode: pose plus angle timeline, no phases, interpreted under Charter only.
- (capability) CAP-6 Protocol gating: a clip below a protocol's view or fps requirement yields explicit unavailable metrics, not guesses.
- (constraint) Force is never measured; only kinematic proxies are reported. Keeps existing non-goal on forces and joint moments.
- (constraint) Missing evidence stays explicit; every observation cites measurement or frame IDs (existing CAP-4 rule).
- (constraint) Monocular 2D MediaPipe in browser remains the engine; angles are screen-plane estimates.
- (constraint) Comparison order: personal baseline first, population norms second.
- (constraint) Squat protocol extraction must reproduce current squat report outputs on the golden fixture within existing tolerance.
- (constraint) Every protocol ships with at least one labeled fixture and declared tolerance before it is enabled.
- (decision) Feasibility tiers: squat and push-up easy (side view, cyclic, planar); free throw workable (side view, >=60 fps, ball untracked); volleyball spike hard (airborne, fast, out-of-plane; needs 120-240 fps and likely 3D).
- (decision) Roadmap order: extract squat to protocol + primitives + body profile; add push-up; add free throw; spike last behind high-fps/3D work.
- (decision) Success signal: push-up added with zero engine code; free throw needs only new primitives, not skill-specific code.
- (constraint) CoM uses published segment mass fractions (de Leva) from 2D landmarks; reported as an estimate.
- (decision) Lazier alternative named: per-skill methodology docs with hand-coded analyzers; rejected because each skill then needs new code.
- (assumption) Population norms are optional; no licensed normative dataset identified.
- (question) Protocol file format: JSON (validated by JSON Schema like AnalysisReport) or YAML?
- (question) Does AnalysisReport need v2 for skill id, phases, and body profile, or can v1 extend additively?
- (question) Ball tracking for free throw and spike: in scope, or release timed from wrist only?
- (question) Who authors and reviews protocol biomechanics claims (citations required per principle)?
- (question) Is multi-person or team-sport tracking out of scope alongside gait, clinical interpretation, forces, and fine-tuning?
- (decision) Companions: charter-principles.md (principle table with proxies plus honesty rules) and skill-protocols.md (protocol fields, primitives, body profile, tiers, roadmap); adopted analysis-report-v1.md and squat-methodology.md.
